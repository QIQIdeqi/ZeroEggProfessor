# 《如果》主界面UI交互设计案 v0.3

> 衔接《如果-剧情策划案.md》的节点表与变量体系。本篇只做**主界面（Title/Main Menu）**的交互设计，不涉及剧情/数值内容的新增或修改。
> **目标平台：PC，键盘输入优先**（鼠标点击同样有效）。
> 本内容为设计草稿参考，正式落地前需经团队评审与合规审核。

## 1. 主界面整体视觉与状态总览

### 1.1 视觉构图说明
延续已确认的HD2D像素风格：背景用一张**静态场景立绘+裂镜动态特效**做主视觉焦点——呼应全剧"镜子"核心道具，而不是用无意义的通用背景图。

- 背景：庆功宴后深夜的空镜头（对应S4-1场景基调），画面中央偏右悬浮一面裂镜，裂缝处有极轻微的紫色光效循环呼吸（0.5~1秒一个周期，弱动画，不抢按钮焦点）
- 标题文字「如果（暂定名）」：左下或居中偏上，像素字体
- 四个按钮：纵向排列于画面左侧或下方三分之一处（具体位置待美术定稿，先给交互逻辑）
- BGM：循环低强度环境音乐，若后续有专门主界面曲可替换

### 1.2 主界面状态机

```
[启动] → 主界面(Idle)
  ├─ 点击"开始游戏" → 新档确认(视是否有存档) → 跳转 S1-1
  ├─ 点击"继续游戏" → 读取最近进度 → 跳转 current_node_id（无存档时此按钮为disabled态，不产生跳转）
  ├─ 点击"退出游戏" → 二次确认弹窗 → 确认则退出程序 / 取消则回到主界面(Idle)
  └─ 点击"设置" → 设置面板(浮层) → 点击返回 → 回到主界面(Idle)
```

主界面本身不产生任何剧情变量写入，纯粹是入口分发层。

## 2. 四按钮详细交互设计

| 按钮 | 触发条件/可用状态 | 点击反馈 | 跳转去向 | 边界情况 |
|---|---|---|---|---|
| **开始游戏** | 始终可点击 | 若已有存档：弹出二次确认"开始新游戏将覆盖当前进度，是否继续？"【确认】/【取消】；若无存档：直接进入 | 确认后清空`current_node_id`并重置全部剧情变量（见第3节变量表），跳转至 S1-1 | 确认覆盖后原存档不可恢复，需在弹窗文案里写明，不做"撤销"功能（降低系统复杂度） |
| **继续游戏** | 有存档时可点击；无存档时按钮置灰(disabled)，不可点击、无点击反馈 | 读取存档中的`current_node_id`及全部变量，直接跳转到对应节点继续播放 | 跳转至存档记录的`current_node_id` | 若存档数据损坏/校验失败，提示"存档读取失败，是否开始新游戏？"【开始新游戏】/【取消】，不静默崩溃 |
| **退出游戏** | 始终可点击 | 弹出二次确认"确定要退出游戏吗？"【确认退出】/【取消】；确认前自动触发一次静默存档(见3.2) | 确认后关闭程序；取消则回到主界面 | 若正在镭像强制点等"仪式感单按钮"节点退出，存档记录当前节点原样，下次继续游戏时从该节点重新进入（不会跳过） |
| **设置** | 始终可点击 | 弹出设置浮层（不打断/不清空主界面状态），浮层内可直接操作，无需二次确认即时生效 | 打开设置浮层，点击浮层内"返回"关闭浮层回到主界面 | 设置浮层打开状态下，背景裂镜动画继续播放，不暂停（设置不是"游戏内暂停菜单"，是独立入口） |

## 3. 存档系统设计（支撑"继续游戏"）

### 3.1 存档策略
建议**单存档位 + 自动存档**，不做多存档位——这是线性叙事+3段镜像回放+1个真分支的流程，叙事体量不大，多存档位会增加UI复杂度却无实际收益。

- 自动存档时机：每个节点推进时自动写入`current_node_id`（即玩家每点一次"继续"或完成一次选择，就静默保存一次，无存档动画/无提示打断沉浸感）
- 手动触发点：退出游戏前额外保存一次，防止自动存档遗漏

### 3.2 新增存档变量（补充到剧情策划案第2节变量表）

| 变量名 | 类型 | 取值范围 | 写入时机 | 用途 |
|---|---|---|---|---|
| `current_node_id` | string | 节点ID（如"S3-2"） | 每个节点推进时 | 记录玩家当前进度，供"继续游戏"读取跳转 |
| `has_save` | bool | true/false | 首次产生存档时置true | 控制"继续游戏"按钮是否可点击 |
| `save_timestamp` | datetime | — | 每次存档时更新 | 可选，仅用于设置面板里"存档管理"展示"上次游玩时间"，不影响剧情逻辑 |

这三个变量和《如果-剧情策划案.md》第2节的`choice_flavor_C1~C7`、`cost_tally`、`mirror_item`、`mirror_path`、`mirror_memory_count`、`ending_branch`一起打包序列化进同一份存档数据。

## 4. 设置面板设计

设置面板为浮层形式，不离开主界面场景。分三区：音频、显示、存档管理。

| 分区 | 设置项 | 交互形式 | 默认值 | 说明 |
|---|---|---|---|---|
| 音频 | BGM音量 | 滑动条 0~100 | 70 | 独立调节背景音乐 |
| 音频 | 音效音量 | 滑动条 0~100 | 80 | UI点击音、场景转场音等 |
| 音频 | 配音音量 | 滑动条 0~100 | 100 | 若后续制作配音；无配音版本可隐藏此项 |
| 显示 | 文字速度 | 三档单选：慢/中/快 | 中 | 影响对白逐字显示的速度，不影响剧情内容 |
| 显示 | 镜像滤镜强度 | 三档单选：标准/减弱/关闭 | 标准 | **无障碍设计**：镜像回放线的紫色滤镜对部分玩家（如色觉敏感人群）可能造成不适，提供减弱/关闭选项，关闭后仍保留裂镜晕影提示但不做整屏变色 |
| 显示 | 画面震动与闪光强度（v0.3新增） | 三档单选：标准/减弱/关闭 | 标准 | **无障碍设计**：对应《如果-剧情策划案.md》S1-4撞击冲击链阶段3"撞击瞬间"的画面震动+vignette闪白/闪红效果。减弱档震动幅度与闪光亮度减半；关闭档保留撞击音效和时间膨胀慢放，但不做画面震动和闪光，照顾光敏感/眩晕敏感玩家 |
| 显示 | 眩晕后效强度（v0.3新增） | 三档单选：标准/减弱/关闭 | 标准 | **无障碍设计**：对应S1-4阶段4"眩晕余波"的画面模糊/重影/降饱和效果及0.4秒继续键延迟响应。减弱档缩短持续时长并降低模糊强度；关闭档保留耳鸣音效和心理flavor文案，但不做画面模糊处理，也取消继续键延迟 |
| 显示 | 画面特效 | 三档单选：完整/标准/精简 | 标准 | PC端标准配置，三档分别对应粒子特效密度（裂镜呼吸光效、转场特效粒子数等），不涉及移动端省电模式 |
| 存档管理 | 当前存档信息 | 只读展示 | — | 展示`current_node_id`对应的章节名称 + `save_timestamp` |
| 存档管理 | 清除存档 | 按钮+二次确认 | — | 弹窗"确定要清除存档吗？此操作不可恢复"【确认清除】/【取消】 |

设置浮层统一提供一个"返回"按钮关闭浮层，所有滑动条/单选项为即时生效（不需要额外"保存设置"按钮，减少操作步骤）。

## 5. 交互组件规格补充

延续《如果-剧情策划案.md》第3节的组件命名风格，新增以下两个组件规格：

6. **二次确认弹窗组件**：统一样式，标题+说明文字+左右两个按钮（左为次要操作如"取消"，右为主要操作如"确认"）。用于"开始游戏覆盖存档""退出游戏""清除存档"三处。支持←→方向键切换高亮按钮+Enter确认。
7. **设置浮层组件**：半透明遮罩+居中卡片，卡片内三个分区纵向排列，右上角固定"返回"按钮；打开/关闭各有一个淡入淡出过渡（约0.2秒），不打断背景主界面动画；支持↑↓方向键在分区项间切换，←→或滑动条专属按键微调数值。

## 6. 异常/边界case汇总

| 场景 | 处理方式 |
|---|---|
| 首次启动，无任何存档 | "继续游戏"按钮disabled态（视觉上变灰），不响应点击 |
| 存档数据损坏或版本不兼容（如后续更新了变量结构） | 读取失败时给出"存档读取失败，是否开始新游戏？"提示，不静默崩溃、不静默丢弹窗 |
| 游玩过程中中途强制退出（如断电、程序崩溃） | 依赖"每节点推进自动存档"机制，下次开游戏时"继续游戏"仍能找到最近一次成功写入的`current_node_id` |
| 设置面板打开时触发"继续游戏"等主界面按钮 | 设置为浮层形态，浮层打开时主界面按钮应不可被点击穿透（标准浮层遮罩交互，防误触） |
